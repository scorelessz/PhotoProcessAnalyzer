## 1. 它是什么（观测）

人社部人事考试中心的**报名照片（证件照）预处理工具**。随包 `使用说明.doc` 说明：报名照片须为 JPG/JPEG、蓝底或白底、宽 ≥295 像素、高 ≥413 像素，处理后约 10 KB，默认文件名 `报名照片.JPG`。

程序本身不做上传，只做「校验 + 裁剪 + 压缩 + 打标记」，真正的上传校验在报名网站服务端。

### 1.1 构建与运行环境（观测）

| 项 | 观测结果 | 依据 |
|---|---|---|
| 编译器/框架 | MFC 4.x（`MFC42.DLL`，纯序号导入）+ MSVC 6 时代工具链 | `ev_040ea1f3…` 导入表 |
| 运行库 | 同时导入 `MSVCRT.dll` 与 **`MSVCRTD.dll`（Debug CRT）** | 同上 |
| 调试痕迹 | `.text` 大量 `0xCC` 填充（`int3`/未初始化栈 `0xCCCCCCCC`），函数序言 `PUSH -1 / PUSH handler / FS:[0]` | 反编译局部变量初始化、字节扫描 |
| 计算机视觉 | OpenCV **1.0**：`cv100.dll`、`cxcore100.dll`、`highgui100.dll`、`ml100.dll` | 导入表 |
| 界面 | 原生 Win32/MFC 对话框 + GDI 位图皮肤，非 Qt/Electron | 资源 + `SendMessage(STM_SETIMAGE, …)` |

这意味着：**这是带调试运行库的 Debug 构建**，发布包必须同时携带 `MSVCRTD.DLL`（不可再分发的调试 CRT），否则无法启动。

### 1.2 随包文件与程序对它们的依赖（观测）

`GetModuleFileNameA → PathRemoveFileSpecA` 取 exe 所在目录，然后拼接三个**相对路径**（`FUN_00402c10` @ `0x402c10`）：

| 文件 | 用途 | 缺失后果 |
|---|---|---|
| `\haarcascade_frontalface_alt2.xml` | OpenCV Haar 正面人脸分类器（`cvLoad`） | 分类器加载失败 → 返回码 1 → 弹「类型不是 JPG/JPEG」提示（提示语与真实原因不符） |
| `\photo.ini` | 全部阈值参数（`GetPrivateProfileStringA` 读 16 个键） | 不致命：全部回落到 exe 内置默认值 |
| `\interface00.bmp` | 「系统处理后图片」区域的展示底图 | 每次打开照片时**由内嵌资源 138 重新生成**，可被覆盖 |

另外 `cv100.dll / cxcore100.dll / highgui100.dll / ml100.dll / cvaux100.dll / cvcam100.dll / cxts001.dll / cxcore100.dll` 等 OpenCV 1.0 DLL 必须与 exe 同目录（DLL 搜索顺序决定）。

## 3. 配置：`photo.ini` 的完整语义（观测）

节名 `[PhotoInfo]`，全部用 `GetPrivateProfileStringA` 读取，缺省值硬编码在 `.data`（`0x5d2000` 起，中文串为 GBK 编码）。

| 键 | exe 内默认值 | 含义（推断） |
|---|---|---|
| `s_min` / `s_max` | `0.05` / `0.3` | 背景饱和度下限/上限（HSV 的 S，归一化 0–1） |
| `i_min` / `i_max` | `0.1` / `0.9` | 背景明度范围（HSV 的 V） |
| `blue_h_min` / `blue_h_max` | `2.5` / `4.5` | 蓝色背景的色相范围（弧度，≈143°–258°） |
| `red_h_min` / `red_h_max` | `0.5` / `5` | 红色/暖色背景的色相范围 |
| `ratio_x_min` / `ratio_x_max` | `0.0` / `0.5` | 人脸左右两侧留白占裁剪框宽度的比例 |
| `ratio_y_min` / `ratio_y_max` | `0.0` / `0.5` | 人脸顶部留白占裁剪框高度的比例 |
| `min_width` / `min_height` | `295` / `413` | 输入照片最小像素 |
| `dst_width` / `dst_height` | `295` / `413` | 输出尺寸（固定） |

随包 `photo.ini` 只覆盖了 4 个键（`s_min=0.05, s_max=0.1, i_min=0.1, i_max=0.7`），其余走默认值。

**注意**：这些是**纯客户端阈值**，可直接改 ini 放宽/收紧；不构成任何安全边界。

## 4. 打开与校验流水线（观测 + 推断）

`FUN_00402c10`（打开按钮）→ `FUN_00401d60` → `FUN_004013a0`。

```
选择文件 (CFileDialog, 过滤 *.jpg;*.jpeg;*.jpe;*.jfif)
  │
  ├─ 读前 2 字节 == FF D8 ?            否 → 返回 1「不是 JPG/JPEG」
  ├─ cvLoadImage(path, CV_LOAD_IMAGE_COLOR)
  └─ FUN_004013a0
       ├─ 1. 读 photo.ini 17 项阈值
       ├─ 2. 宽 < min_width 或 高 < min_height → 返回 2「像素数低」
       ├─ 3. 背景检查 FUN_00401070 → 不一致/不合格 → 返回 3「背景不符合」
       │      · 采样 3 个 3×3 邻域：
       │        (0.10W, 0.10H)、(0.10W, 0.25H)、(0.90W, 0.167H)
       │      · 均值 /255 后 RGB→HSV（H 用 acos 公式，S=1-3·min/Σ，V=Σ/3）
       │      · 每块判为「白」(S≤s_min，V∈[i_min,i_max]…)
       │        或「蓝/红」(H 落在配置色相区间)
       │      · 三块结论须完全一致，否则判 3（不合格）
       ├─ 4. cvLoad(haarcascade_frontalface_alt2.xml)
       │      cvHaarDetectObjects(灰度图, cascade, storage,
       │                          scale_factor≈1.1, min_neighbors≈2,
       │                          flags=1, min_size=30×30)
       │      未检出 → 返回 5「不符合要求（非正面人像）」
       ├─ 5. 取「最大人脸」（比较第 3 个字段，即宽度 w）
       │      要求 w / 图像宽 ≥ 0.32，否则 → 返回 5
       ├─ 6. 以人脸为中心扩框（上下左右按比例扩展），
       │      按目标宽高比 295:413 修正裁剪框（偏差>10% 时再调整）
       │      校验左/右留白 ∈ [ratio_x_min, ratio_x_max]
       │           顶部留白 ∈ [ratio_y_min, ratio_y_max]
       │      不满足 → 返回 4「人头比例不符合要求」
       └─ 7. cvSetImageROI + cvCreateImage(295,413,8,3) + cvResize(LINEAR)
              → 返回 0，输出裁剪后的 IplImage
```

### 返回码 ↔ 界面提示（观测，`0x402c10` 的 switch）

| 码 | 含义 | 提示文本（`.data` 地址） |
|---|---|---|
| 0 | 通过 | —（合成预览） |
| 1 | 非 JPEG / 分类器或图像加载失败 | `0x5d2220`「打开照片文件类型不是JPG/JPEG格式，请选择JPG/JPEG格式照片文件。」 |
| 2 | 像素不足 | `0x5d21e0`「打开照片文件像素数低。请选择高于或符合像素数要求的照片文件。」 |
| 3 | 背景不合格 | `0x5d21a4`「打开照片文件背景不符合要求。请选择白色或蓝色背景照片文件。」 |
| 4 | 头肩比例不合格 | `0x5d2160`「打开照片文件人像头部比例不符合要求。请选择头部比例适当的照片文件。」 |
| 5 | 未检出人脸 | `0x5d2124`「打开照片文件不符合要求。请选择正面人像标准证件照片文件。」 |

### 预览合成（观测，易被忽略的副作用）

通过校验后，`0x402c10` 会：

1. `cvLoadImage("…\interface00.bmp")`（该文件刚由内嵌资源 138 重写）；
2. `cvSetImageROI(bmp, 127, 182, 175, 228)` —— 把 295×413 的结果缩放进底图固定区域；
3. `cvSaveImage` **覆盖写回 `interface00.bmp`**；
4. `LoadImageA` + `STM_SETIMAGE` 显示。

因此程序**会修改自身安装目录下的文件**，在只读目录（Program Files、只读共享盘、iCloud 只读副本）中会失败或显示异常。

## 5. 保存流水线（观测）

`FUN_00403010`（保存按钮，`0x403010`）：

1. `CFileDialog` 另存为，默认名 `报名照片.jpg`（`0x5d231c`），过滤器 `*.jpg;*.jpeg;*.jpe;*.jfif`；
2. 若文件名末尾不是 `.jpg`（`CString::Right(4)` 与 `0x5d2314` = `".jpg"` 比较），自动补 `.jpg`；
3. `cvSaveImage(path, img, 0)` —— OpenCV 默认 JPEG 质量（≈95）；
4. `CImage` 重新加载 → 设置 **quality = 40.0f**（`0x42200000`）→ 另存，把体积压到 10 KB 量级；
5. `FUN_00401e10`：以 `"rb+"` 打开文件，`fseek(SEEK_END)`，**追加 10 字节**：

```
FF 02 00 08 67 6A 67 77 79 32
              g  j  g  w  y  2
```

（汇编逐字节确认：`ev_ddd40d8e…`，`MOV BYTE PTR [ESP+0x20],0xFF / …0x2 / …0x0 / …0x8 / 'g' / 'j' / 'g' / 'w' / 'y' / '2'`）

6. 释放图像、恢复占位图、`MessageBox("照片已保存成功，是否退出", "保存照片", MB_YESNO)`，选「是」则关闭对话框。

### 关于这 10 字节标记（推断）

- 它**不是**标准 JPEG APP2（APP2 应为 `FF E2`，这里是 `FF 02`），也不是合法段；解码器会忽略它。
- `"gjgwy2"` 高度疑似「**国考公务员 2**」拼音缩写，配合「人社部人事考试中心」背景，最合理的解释是：**报名网站服务端会检查文件末尾这段固定标记**，用于区分「本工具处理过的照片」与「直接改扩展名/其他工具生成的照片」。
- 该标记是**静态常量**，任何人手工追加同样 10 字节即可伪造；它不构成防篡改机制，只可能是上传端的弱校验。
- 观测范围仅限本 exe，服务端如何校验属【未知】。

## 7. 可靠性与安全性观察

**观测：**

1. Debug 构建：`MSVCRTD.dll` 依赖、`0xCC` 填充、`chkesp`、`_CxxThrowException`、`_assert`。
2. 无数字签名/完整性校验；无 WinINet/WinHTTP/WinSock 应用层调用证据（仅导入 4 个 WS2_32 序号，静态无法确认是否被调用 →【未知】）。
3. 类型判定只看 `FF D8` 两字节，不校验完整结构；`cvLoadImage` 才是真正的解码器。
4. 校验失败提示与实际原因不对应（分类器缺失报「不是 JPG」）。
5. 只在客户端校验，`photo.ini` 可随意修改以放宽所有阈值。
6. 保存时会覆盖写 `interface00.bmp`；每次打开照片都会用内嵌资源重建它，即**安装目录必须可写**。
7. 只接受 JPEG 容器（PNG 改名 JPG 会在解码阶段失败）。

**推断的风险点：**

- 静态 10 字节标记可伪造 → 上传端若仅依赖它，等同无效校验。
- 头肩比例、背景、人脸检测都是本地启发式（Haar + 3 个 3×3 采样），误判率高（深色衣服/纯色背景/侧脸/遮挡）。
- 客户端阈值可绕过，真正的合规性只能由服务端复核。
